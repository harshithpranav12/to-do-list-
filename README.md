# Daymark To-Do List

A beginner-friendly full-stack task manager built with Java 17, Spring Boot, Spring Data JPA, H2, and plain HTML/CSS/JavaScript. The browser talks to a REST API; tasks are saved in a local file-based H2 database, so they survive application restarts.

## What is in the project

```text
src/main/java/com/example/todolist/
  TodoApplication.java          Spring Boot entry point
  task/
    Task.java                   JPA entity (database row)
    Priority.java               LOW, MEDIUM, HIGH values
    TaskRepository.java         Database access through Spring Data JPA
    TaskService.java            Task rules and application logic
    TaskController.java         HTTP REST endpoints
    TaskRequest.java             Validated input DTO
    TaskResponse.java            Output DTO
    StatusRequest.java           Completion update DTO
    ApiExceptionHandler.java     Consistent API error responses
src/main/resources/
  application.properties       File-based H2 configuration
  static/                       Browser app (HTML, CSS, JavaScript)
src/test/java/                  API integration tests
```

The controller receives JSON over HTTP, validates the request, and calls the service. Spring injects the service and repository into the classes that need them (dependency injection). The service applies the task operations and calls the repository. Spring Data JPA turns repository calls into database queries and maps the `Task` entity to the `tasks` table. The controller returns DTOs as JSON, which the browser renders.

Annotations such as `@RestController`, `@GetMapping`, and `@Entity` tell Spring how to connect HTTP routes and Java classes to its runtime. REST uses familiar HTTP verbs: `GET` reads, `POST` creates, `PUT` replaces editable fields, `PATCH` changes completion, and `DELETE` removes. Bean Validation annotations reject bad input before it reaches the database.

## Prerequisites

- JDK 17 or newer (JDK 17 is the project target)
- Maven 3.6 or newer
- Git

Check your tools with `java -version` and `mvn -version`. The Maven command must run with a JDK that supports Java 17 builds.

## Run locally

```bash
mvn spring-boot:run
```

Open [http://localhost:8080](http://localhost:8080). The H2 console is at [http://localhost:8080/h2-console](http://localhost:8080/h2-console), using JDBC URL `jdbc:h2:file:./data/todolist`, username `sa`, and a blank password. The `data/` directory is ignored by Git because it contains your local task data.

To stop the server, press Ctrl+C. Run tests with `mvn test`; package the app with `mvn clean package`, then run the jar with `java -jar target/todo-list-0.0.1-SNAPSHOT.jar`.

## API

All endpoints return JSON except `DELETE`, which returns `204 No Content`. Priority must be `LOW`, `MEDIUM`, or `HIGH`; dates use ISO format `YYYY-MM-DD`.

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/tasks` | Create a task (`201 Created`) |
| `GET` | `/api/tasks` | List tasks |
| `GET` | `/api/tasks/{id}` | Get one task |
| `PUT` | `/api/tasks/{id}` | Update title, description, priority, and due date |
| `PATCH` | `/api/tasks/{id}/status` | Set completed status |
| `DELETE` | `/api/tasks/{id}` | Delete a task |

List filters can be combined: `/api/tasks?completed=false&priority=HIGH`.

Create request:

```json
{
  "title": "Prepare project demo",
  "description": "Show the task form and filters",
  "priority": "HIGH",
  "dueDate": "2026-11-05"
}
```

Response (timestamps and ID are generated by the server):

```json
{
  "id": 1,
  "title": "Prepare project demo",
  "description": "Show the task form and filters",
  "completed": false,
  "priority": "HIGH",
  "dueDate": "2026-11-05",
  "createdAt": "2026-11-01T10:30:00",
  "updatedAt": "2026-11-01T10:30:00"
}
```

Change completion with `PATCH /api/tasks/1/status` and body `{"completed":true}`. Validation and missing-task failures use a JSON body with `timestamp`, `status`, `error`, `message`, and `details`.

Quick API examples with curl:

```bash
curl -X POST http://localhost:8080/api/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Learn Spring","description":"Build one feature","priority":"MEDIUM","dueDate":null}'

curl 'http://localhost:8080/api/tasks?completed=false&priority=MEDIUM'
curl -X PATCH http://localhost:8080/api/tasks/1/status \
  -H 'Content-Type: application/json' -d '{"completed":true}'
```

## H2 and MySQL

H2 is an embedded relational database. JPA maps each `Task` object to a row, with the entity's fields mapped to columns. The file URL in `application.properties` keeps local records between restarts. `spring.jpa.hibernate.ddl-auto=update` creates/updates the table during development.

To use MySQL, add the MySQL Connector/J runtime dependency to `pom.xml`, create a database, and set these values in an untracked `application-local.properties` (or environment variables) instead of committing credentials:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/todolist
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
spring.jpa.hibernate.ddl-auto=update
```

Set `SPRING_PROFILES_ACTIVE=local` after adding `spring.profiles.active` configuration to load that profile. For a real deployment, replace `ddl-auto=update` with managed schema migrations.

## Push to GitHub

Create an empty repository on GitHub, then from this project folder:

```bash
git init
git add .
git commit -m "Build full-stack to-do list app"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Replace the remote URL with the one GitHub shows for your repository. Never commit passwords, local database files, or personal tokens.
